# DSH Desktop Host plugin

This package runs only in official DeepSeek Harness Desktop `0.2.0-rc.2`. It uses injected `sessionController` and `workspaceRegistry` services and publishes an authenticated loopback endpoint for the separate MCP package.

Install it through Desktop's Plugins page with an absolute built package-directory or external tarball path. A first install should report `application: "applied"` through HMR. Package replacement or edits to an already installed source may require an operator-owned Desktop restart.

The JavaScript bundle includes the private bridge protocol runtime. Desktop-owned Cordis, Schemastery, session-controller, and Workspace capabilities remain exact external peers supplied by the Host. Delegation reuses a unique same-title Workspace only when its canonical path equals the task directory; ambiguous or different-directory matches are rejected before creating a Session. With no match, it creates an ungrouped Session at that directory. It never registers a Workspace. Update this package together with the MCP package to `0.2.3`. See the [repository README](<../../README.en.md>) for configuration, security, and acceptance cases.

Assistant-message projection retains `data.turn`, `data.step`, and `data.message` with its ID, role, and every content block, including reasoning. `data.message.source` retains only string kind/provider/model fields; internal `data.stream` and source replay state are omitted. Lifecycle and error event data is preserved. If the complete serialized event fits within 4 KiB, its projected data stays unchanged. Larger data is serialized as JSON and split into consecutive fragments using flat `data: { bridgeContentChunk: true, id, index, total, encoding: "json", text }`. The shared ID is the first chunk's cursor, indexes start at zero, and every serialized event stays within 4 KiB.

Pages keep the serialized `events` array within 16 KiB and include required `hasMore`. Consumers must continue from `nextCursor` while it is true, independently of execution status, and reconstruct each chunk group only after every index is present. The in-memory ring still defaults to 512 entries and supports at most 4096; each chunk consumes one entry. History can expire, so `truncated` gaps or missing chunk indexes mean incomplete data. See [complete event consumption](<../../docs/reference.md#完整事件读取--complete-event-consumption>). This release has not been installed or accepted on a live Desktop.
