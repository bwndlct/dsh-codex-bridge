# MCP server

This package provides the `dsh-codex-bridge-mcp` stdio MCP server. It reads the owner-only discovery file written by the Desktop host plugin and exposes `dsh_delegate`, `dsh_status`, `dsh_follow`, `dsh_wait`, and `dsh_cancel`.

It never starts DeepSeek Harness, invokes a model API, or edits persisted sessions.

Always pass the current Codex task's absolute working directory as `cwd` to `dsh_delegate`. Missing or relative `cwd` is rejected; `DSH_DEFAULT_WORKSPACE_CWD` and the MCP process directory are not task-directory fallbacks. A same-title Workspace must be unique and resolve to the task directory; ambiguity or a different path is rejected before Session creation. With no match, the Session uses the default ungrouped section at canonical `cwd`. No Workspace is registered. Unmatched responses omit `workspace.id`.

Update this package together with the Desktop plugin to `0.2.3`. `dsh_wait` and `dsh_follow` return bounded event pages once as JSON in `content[0].text`, without duplicating them in `structuredContent`. Both responses require `hasMore`: when true, continue with `dsh_follow` from the page's `nextCursor` until false. `status.terminal` only reports execution completion; `status.lastCursor` must never replace the consumed cursor. If execution is still running after the backlog is drained, keep using that consumed cursor for later follow/wait calls.

Deduplicate events by their event `cursor`. Data that fits within a complete serialized event of 4 KiB remains unchanged after the plugin's assistant-message projection; larger data uses flat `data: { bridgeContentChunk: true, id, index, total, encoding: "json", text }` fragments. The shared `id` is the first chunk's cursor. Collect all `index = 0..total-1` across pages for each ID, join `text` in order with `join('')`, then `JSON.parse` once to restore the original projected `data`. Do not discard subsequent chunks by their shared ID or durable sequence, and never treat the final chunk alone as the complete answer. The projection retains every message content block, including reasoning, while omitting internal stream and source replay metadata.

Each serialized page's `events` array stays within 16 KiB. The plugin's ring defaults to 512 entries (configurable up to 4096); every chunk takes an entry and may expire. `truncated` indicates a retained-history gap, and missing chunk indexes also mean incomplete data, even when `hasMore` is false or execution is terminal. Report the gap rather than presenting a partial answer as complete. The five tools, fixed HTTP routes, request parameters, and timeout behavior remain unchanged. A transport timeout is an unknown delegation outcome, not permission to resend; reconcile known Session IDs or inspect Desktop before retrying. See [complete event consumption](<../../docs/reference.md#完整事件读取--complete-event-consumption>) for the full contract. No live Desktop installation or acceptance was performed for `0.2.3`.

`reasoningEffort` can be supplied with or without `model`. Without `model`, it is validated against the Host current default model and applied before prompt admission. Unsupported efforts or an unavailable default produce an error rather than being ignored. The official Host model-selection API also saves the selection as its default in the background.
